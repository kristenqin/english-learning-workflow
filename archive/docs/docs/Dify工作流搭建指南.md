## 飞书多维表格配置

### 第一步：创建飞书多维表格

1. **访问飞书多维表格**
   - 打开飞书，点击左侧导航栏的"多维表格"
   - 或直接访问：https://www.feishu.cn/product/base

2. **创建新表格**
   - 点击"新建多维表格"
   - 命名为：`英语单词学习记录`

3. **设置表格字段**（按顺序创建以下列）：

   | 字段名称 | 字段类型 | 说明 |
   |---------|---------|------|
   | 单词 | 文本 | 存储单词本身 |
   | 定义 | 文本 | 第一性原理定义 |
   | 例句 | 文本 | 具体使用例句 |
   | 解释 | 文本 | 对例句的解释 |

   💡 **操作提示**：点击表格右侧的 `+` 号添加新列，选择"文本"类型

### 第二步：创建飞书应用获取凭证

1. **访问飞书开放平台**
   - 打开：https://open.feishu.cn/app
   - 登录你的飞书账号

2. **创建企业自建应用**
   - 点击"创建企业自建应用"
   - 应用名称：`Dify英语学习`
   - 应用描述：`用于 Dify 写入英语学习数据`
   - 上传一个应用图标（可选）

3. **配置应用权限**
   - 在应用管理页面，点击左侧"权限管理"
   - 搜索"多维表格"，开通以下权限：
     - ✅ `bitable:app`（查看、编辑和管理多维表格）
     - ✅ `bitable:app:readonly`（查看多维表格）
   - 点击"保存"

4. **获取凭证信息**
   - 点击左侧"凭证与基础信息"
   - 记录以下信息（后面会用到）：
     - **App ID**：`cli_xxxxxxxxxxxxx`
     - **App Secret**：点击"查看"获取

5. **发布应用版本**
   - 点击左侧"版本管理与发布"
   - 创建版本并发布（选择"所有员工"可用）

### 第三步：获取表格 Token 和 Table ID

1. **打开你创建的多维表格**

2. **从 URL 中提取信息**

   表格的 URL 格式如下：
   ```
   https://xxx.feishu.cn/base/APP_TOKEN?table=TABLE_ID&view=VIEW_ID
   ```

   **示例**：
   ```
   https://example.feishu.cn/base/bascnABCDefgh1234567890?table=tblXYZ9876543210&view=vewABC123
   ```

   从这个 URL 中提取：
   - **APP_TOKEN**：`bascnABCDefgh1234567890`（base/ 后面的部分）
   - **TABLE_ID**：`tblXYZ9876543210`（table= 后面的部分）

3. **记录这些信息**（创建一个临时文档保存）：
   ```
   App ID: cli_xxxxxxxxxxxxx
   App Secret: xxxxxxxxxxxxxxxx
   App Token: bascnABCDefgh1234567890
   Table ID: tblXYZ9876543210
   ```

### 步骤 3：添加代码节点 - 解析单词列表

1. **添加节点**
   - 点击"开始"节点右侧的 `+` 号
   - 选择"代码"节点

2. **配置代码节点**
   - **节点名称**：`解析单词列表`

   - **输入变量**：
     - 点击"添加变量"
     - 变量名：`word_list_text`
     - 引用：选择 `开始 / word_list_text`

   - **代码语言**：选择 `Python3`

   - **代码内容**：
   ```python
   def main(word_list_text: str) -> dict:
       """
       将输入的文本按行分割成单词列表
       """
       lines = word_list_text.strip().split('\n')
       words = [line.strip() for line in lines if line.strip()]

       return {
           "words": words,
           "total_count": len(words)
       }
   ```

   - **输出变量**：
     - 变量 1：`words`，类型：`Array[String]`
     - 变量 2：`total_count`，类型：`Number`

### 步骤 5：【迭代内部】添加 LLM 节点 - 生成定义和例句

> 📌 注意：以下步骤都在"遍历单词列表"迭代节点的**内部**进行

1. **添加 LLM 节点**
   - 在迭代内部画布，点击 `+` 添加节点
   - 选择"LLM"节点

2. **配置 LLM 节点**
   - **节点名称**：`生成定义和例句`

   - **选择模型**：
     - 模型提供商：`DeepSeek`
     - 模型：`deepseek-chat`

   - **模型参数**：
     - Temperature：`0.7`
     - Max Tokens：`2000`

   - **提示词**：
   ```
   请以第一性原理的风格对单词 "{{#1734467918812.item#}}" 给出定义，只用一句话总结其本质，不要多余分析或推导。
   然后列出至少 10 个不同场景下的具体使用例句，让我可以感受这个单词在不同语境下的使用感受。

   输出格式如下：
   1️⃣ 定义（第一性原理一句话）：
   {{#1734467918812.item#}} — {一句话总结定义}

   2️⃣ 场景示例：
   - {示例句子1}
   - {示例句子2}
   …
   - {示例句子10}
   ```

   💡 **重要提示**：`{{#1734467918812.item#}}` 这个变量引用的数字部分是系统自动生成的迭代节点ID，你需要：
   - 在提示词输入框中，输入 `{{` 会弹出变量选择
   - 选择 `遍历单词列表 / item`（当前迭代的单词）

3. **点击"保存"**

### 步骤 6：【迭代内部】添加代码节点 - 解析定义和例句

1. **添加代码节点**
   - 在"生成定义和例句"节点后添加"代码"节点

2. **配置代码节点**
   - **节点名称**：`解析定义和例句`

   - **输入变量**：
     - 变量 1：`llm_output`，引用：`生成定义和例句 / text`
     - 变量 2：`current_word`，引用：`遍历单词列表 / item`

   - **代码内容**：
   ```python
   import re

   def main(llm_output: str, current_word: str) -> dict:
       """
       解析LLM输出，提取定义和例句列表
       """
       try:
           lines = llm_output.strip().split('\n')

           # 提取定义
           definition = ""
           for line in lines:
               if '—' in line or '–' in line or '-' in line:
                   # 提取 "单词 — 定义" 格式
                   parts = re.split('[—–-]', line, 1)
                   if len(parts) == 2:
                       definition = parts[1].strip()
                       break

           # 如果没找到，尝试其他方式
           if not definition:
               for i, line in enumerate(lines):
                   if '定义' in line and i + 1 < len(lines):
                       definition = lines[i + 1].strip()
                       break

           # 提取例句（以 - 或 • 开头的行）
           sentences = []
           for line in lines:
               line = line.strip()
               if line.startswith('-') or line.startswith('•') or line.startswith('*'):
                   sentence = line.lstrip('-•* ').strip()
                   if sentence:
                       sentences.append(sentence)

           return {
               "definition": definition if definition else "定义提取失败",
               "sentences": sentences,
               "sentence_count": len(sentences)
           }
       except Exception as e:
           return {
               "definition": f"解析错误: {str(e)}",
               "sentences": [],
               "sentence_count": 0
           }
   ```

   - **输出变量**：
     - 变量 1：`definition`，类型：`String`
     - 变量 2：`sentences`，类型：`Array[String]`
     - 变量 3：`sentence_count`，类型：`Number`

3. **点击"保存"**

### 步骤 8：【第二层迭代内部】添加 LLM 节点 - 解释例句

> 📌 注意：现在在第二层迭代"遍历例句列表"的**内部**

1. **添加 LLM 节点**
   - 在迭代内部添加"LLM"节点

2. **配置 LLM 节点**
   - **节点名称**：`解释例句用法`

   - **选择模型**：
     - 模型提供商：`DeepSeek`
     - 模型：`deepseek-chat`

   - **模型参数**：
     - Temperature：`0.7`
     - Max Tokens：`500`

   - **提示词**：
   ```
   对于下面的单词，我给出了第一性原理定义：
   {{#1734467918812.item#}} — {{#1734468234567.definition#}}

   请根据这个定义解释句子中该单词的使用。只输出一句话，完整表达句子中该单词所体现的：

   动作（动词体现的行为或过程）

   状态（名词或形容词体现的存在或属性）

   影响/掌控关系（副词、抽象名词、功能词体现的作用、影响或关系）

   不要做额外解释或分析。

   例子：
   定义：take — 通过接触或意志将某物从外界引入自身掌控之中
   输入：He took a deep breath.
   输出：他通过意志将外界的空气引入身体，使之成为自身掌控的呼吸。

   ```

   💡 **变量引用说明**：
   - `{{#1734467918812.item#}}`：选择 `遍历单词列表 / item`（当前单词）
   - `{{#1734468234567.definition#}}`：选择 `解析定义和例句 / definition`（定义）
   - `{{#1734468456789.item#}}`：选择 `遍历例句列表 / item`（当前例句）

3. **点击"保存"**

### 步骤 9：【第二层迭代内部】添加 HTTP 节点 - 写入飞书

1. **添加 HTTP 节点**
   - 在"解释例句用法"节点后添加"HTTP 请求"节点

2. **配置 HTTP 节点**
   - **节点名称**：`写入飞书表格`

   - **请求方法**：`POST`

   - **URL**：
   ```
   https://open.feishu.cn/open-apis/bitable/v1/apps/{YOUR_APP_TOKEN}/tables/{YOUR_TABLE_ID}/records
   ```

   ⚠️ **替换说明**：
   - `{YOUR_APP_TOKEN}`：替换为你记录的 App Token（如 `bascnABCDefgh1234567890`）
   - `{YOUR_TABLE_ID}`：替换为你记录的 Table ID（如 `tblXYZ9876543210`）

   **示例**：
   ```
   https://open.feishu.cn/open-apis/bitable/v1/apps/bascnABCDefgh1234567890/tables/tblXYZ9876543210/records
   ```

   - **Headers（请求头）**：
   ```json
   {
     "Content-Type": "application/json",
     "Authorization": "Bearer YOUR_FEISHU_APP_TOKEN"
   }
   ```

   ⚠️ **获取 Bearer Token**：

   这里需要先获取飞书的访问令牌。你有两个选择：

   **选择 A：使用 tenant_access_token（推荐）**

   需要先调用飞书 API 获取 token：
   ```bash
   curl -X POST 'https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal' \
     -H 'Content-Type: application/json' \
     -d '{
       "app_id": "YOUR_APP_ID",
       "app_secret": "YOUR_APP_SECRET"
     }'
   ```

   返回的 `tenant_access_token` 有效期 2 小时。

   **选择 B：在 Dify 中添加自定义变量（更优雅）**

   1. 在工作流顶部，点击"环境变量"
   2. 添加变量：
      - 名称：`FEISHU_TOKEN`
      - 类型：`密钥`
      - 值：你的 tenant_access_token
   3. 在 Headers 中使用：`Bearer {{#env.FEISHU_TOKEN#}}`

   - **Body（请求体）**：
   ```json
   {
     "fields": {
       "单词": "{{#1734467918812.item#}}",
       "定义": "{{#1734468234567.definition#}}",
       "例句": "{{#1734468456789.item#}}",
       "解释": "{{#1734469123456.text#}}"
     }
   }
   ```

   💡 **变量引用**：
   - `单词`：选择 `遍历单词列表 / item`
   - `定义`：选择 `解析定义和例句 / definition`
   - `例句`：选择 `遍历例句列表 / item`
   - `解释`：选择 `解释例句用法 / text`

   ⚠️ **字段名称必须完全匹配**：
   - 这里的 `"单词"`、`"定义"`、`"例句"`、`"解释"` 必须与你飞书表格中的字段名完全一致（包括中文字符）

3. **点击"保存"**

## 获取飞书 Access Token 的完整方案

由于飞书的 access token 会过期，这里提供一个更完善的解决方案：

### 方案 1：在工作流开始时获取 Token（推荐）

在主工作流的最开始添加一个 HTTP 节点来获取 token：

1. **添加 HTTP 节点**（在"解析单词列表"之前）
   - 节点名称：`获取飞书Token`
   - 方法：`POST`
   - URL：`https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal`
   - Headers：
   ```json
   {
     "Content-Type": "application/json"
   }
   ```
   - Body：
   ```json
   {
     "app_id": "YOUR_APP_ID",
     "app_secret": "YOUR_APP_SECRET"
   }
   ```

2. **在后续的写入节点中引用**
   - Authorization：`Bearer {{#获取飞书Token.body.tenant_access_token#}}`

### 方案 2：使用飞书长期 Token（如果可用）

如果你的飞书版本支持，可以在飞书开放平台生成长期有效的 Access Token。

## 常见问题

### Q1: 飞书 API 返回 401 错误

**原因**：Access Token 过期或无效

**解决方案**：
- 检查 App ID 和 App Secret 是否正确
- 重新获取 tenant_access_token
- 建议使用"方案 1"在工作流中动态获取 token

### Q2: 飞书 API 返回 403 错误

**原因**：权限不足

**解决方案**：
- 检查应用是否开通了"多维表格"权限
- 检查应用是否已发布
- 确认用户有访问该表格的权限

### Q3: 字段名称不匹配错误

**原因**：HTTP Body 中的字段名与飞书表格字段名不一致

**解决方案**：
- 打开飞书表格，检查字段名称（包括中文、空格）
- 确保 HTTP Body 中的字段名完全一致

### Q4: LLM 节点超时

**原因**：DeepSeek API 响应慢或配额用尽

**解决方案**：
- 检查 DeepSeek API Key 是否有效
- 检查 API 配额是否充足
- 适当增加节点的超时时间

### Q5: 例句解析失败

**原因**：LLM 输出格式不符合预期

**解决方案**：
- 调整 prompt1，让输出格式更严格
- 优化"解析定义和例句"的代码逻辑
- 可以先用少量单词测试，观察 LLM 输出格式

### Q6: 处理大量单词时很慢

**原因**：
- 串行处理，每个单词需要调用多次 LLM
- 每个单词 10 个例句，每个例句又要调用一次 LLM

**优化方案**：
- 第一层迭代（遍历单词列表）开启"并行模式"
- 减少每个单词的例句数量（修改 prompt1）
- 分批处理单词

### Q7: 如何查看详细错误日志

**解决方案**：
1. 在工作流运行界面，点击报错的节点
2. 查看"输出"标签页的错误信息
3. 检查 HTTP 节点的响应内容
4. 使用 Dify 的日志功能查看详细日志

## 进阶优化建议

### 1. 添加数据去重
在写入飞书前，检查是否已存在相同的单词+例句组合，避免重复数据。

### 2. 添加错误通知
当处理失败时，发送通知（如飞书机器人消息、邮件等）。

### 3. 批量导入优化
使用飞书的批量写入 API，减少 HTTP 请求次数。

### 4. 添加进度显示
使用 Dify 的变量聚合器节点，统计处理进度并输出。

### 5. 数据本地缓存
先将所有结果缓存到 Dify 变量中，最后一次性写入飞书，避免部分失败。
